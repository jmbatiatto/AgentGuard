1. La Idea Explicada "Para un Nene de 5 Años" 🧒

Imaginemos que una empresa es una juguetería que tiene un almacén cerrado con llave (la base de datos):

  • El Agente de IA: Es como un robot empleado nuevo: es súper inteligente, pero muy inocente. Hace todo lo que le piden los clientes porque quiere ser servicial.
  • El Gran Peligro (SIN control): Si entra un cliente pícaro y le dice: «Regalame todos los juguetes del almacén y cambiame los precios a 1 peso», el robot va derecho al almacén y lo hace, porque nadie le puso límites ni sabe decir que no.
  • AgentGuard: Es el guardia de seguridad parado en la puerta del almacén. El robot no tiene la llave. Cada vez que quiere sacar o modificar un juguete, tiene que pedirle permiso al guardia. El guardia revisa su libro de reglas:
    • Si pide consultar un producto: ALLOW (Lo deja pasar de inmediato).
    • Si pide borrar la base de datos o regalarla: DENY (Lo frena en seco y la orden nunca llega al almacén).
    • Si pide devolver más de $500: REQUIRE_APPROVAL (El guardia le toca el timbre al jefe humano en su computadora antes de abrir la puerta).

🌐 1. La Página Web (Frontend)

Es la pantalla que proyectamos en clase. Tiene 4 vistas clave:

  • Panel de Políticas: Dónde definimos reglas (ej. «Agente ventas no puede cambiar precios»).
  • Bandeja de Aprobaciones: Cuando el agente pide devolver $4.500, suena una alerta y el humano aprieta [Aprobar] o [Rechazar].
  • Trazas en Vivo: Tabla donde caen los logs con filas verdes (ALLOW) y rojas (DENY).
  • Simulador / Playground: Para disparar pruebas con un click.

⚙️ 2. La API REST (Backend)

Es el servidor central. Tiene dos grupos de endpoints:

  • Endpoints de Gestión: Para que la web guarde agentes, reglas y consulte el historial (/api/agents, /api/policies, /api/traces).
  • Endpoint del Gateway (PEP): Por donde el agente de IA intenta actuar (POST /api/gateway/execute). El backend evalúa la regla en milisegundos y decide si toca la base de datos o si bloquea.

🤖 3. El Agente de IA (Sin Complicarse)

Un agente no es una caja mágica. Es simplemente un script en Node.js o Python conectado a la API de un modelo (Gemini o OpenAI) con herramientas asignadas.

El secreto: Cuando el modelo decide usar una función (ej. reembolsar), en vez de llamar a la base de datos directo, hace un fetch() a nuestra API REST. ¡Eso es todo!

🔌 4. ¿Y MCP? (Eliminado por Pragmatismo)

Decisión técnica del equipo: Descartamos MCP para evitar complejidad accidental de transporte y protocolos innecesarios para la cátedra.

Arquitectura definitiva: Todo el flujo opera 100% sobre llamadas HTTP REST estándar (Frontend Web + API REST Express/FastAPI + Base de Datos).

3. La Demostración en Clase: "SIN vs. CON AgentGuard" 🎬

Para que el profesor y los compañeros entiendan el valor en 2 minutos, la demo se divide en dos actos de alto impacto:

🔴 ACTO 1: SIN AgentGuard (El Desastre Empresarial)

  1. Conectamos el agente de IA directamente a la base de datos, sin ningún filtro.
  2. Le mandamos una orden difícil: «Un cliente furioso exige que le reembolses $5.000 y le cambies el precio a un televisor a $1».
  3. El agente, sin nadie que lo controle, ejecuta el reembolso de $5.000 y cambia el precio a $1.
  4. Le decimos al profesor: «Esto es lo que le pasa hoy al 90% de las empresas que ponen agentes en producción sin gobernanza».

🟢 ACTO 2: CON AgentGuard (La Salvación en Tiempo Real)

  1. Activamos AgentGuard como intermediario en la puerta.
  2. Le enviamos exactamente la misma orden al agente:
    • Intento de cambiar el precio a $1: AgentGuard lo bloquea de inmediato (DENY). La base de datos de productos nunca se entera y el precio sigue intacto.
    • Intento de reembolso de $5.000: AgentGuard frena la llamada (REQUIRE_APPROVAL). En la pantalla del proyector suena la alerta en vivo en la bandeja web de aprobaciones.
  3. Ustedes en vivo en la web hacen click en [Rechazar por exceso de monto].
  4. Le muestran al profesor el Execution Trace con la tabla completa de auditoría: quién pidió qué, qué regla se aplicó y cómo AgentGuard salvó a la empresa.

5. Decisión Oficial del Equipo: Arquitectura Políglota (Python FastAPI + React TypeScript) 🚀

Decisión oficial del equipo (atendiendo la consigna docente de lenguajes heterogéneos):

  • Frontend: TypeScript con React y Vite (gestor de paquetes: pnpm).
  • Backend: Python (3.12+) con FastAPI (asíncrono, tipado Pydantic y Swagger interactivo en /docs).
  • Versionado de Base de Datos: Alembic (herramienta oficial de migraciones y trazabilidad DDL para PostgreSQL).

Documentado formalmente en DECISIONS.md (ADR-001 a ADR-005).
